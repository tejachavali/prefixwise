# E-route, live: two vLLM 0.33.0 replicas behind a router (Colab L4, 2026-11-08)

**Result: PASS.** With the router alternating, every turn sent to the replica that had never
seen the session was named a **confirmed** `routing_miss` from the replicas' KV events alone
(5/5). With the router sticky (control), every second turn was a hit (5/5). No false claim.

| | alternate T2 | sticky T2 (control) |
|---|---|---|
| expected | `routing_miss`, confirmed | `none` (hit) |
| measured | **5/5** confirmed | **5/5** hits |
| cached tokens | 0 of ~1,650 | ~1,600 of ~1,650 |

**Setup.** Colab L4, one GPU. vLLM 0.33.0, two servers of Qwen/Qwen3-1.7B on it
(`--gpu-memory-utilization 0.42 --max-model-len 8192`), HTTP ports 8001/8002, KV events on
`tcp://*:5557` / `tcp://*:5558` (`experiments/e1_open/vllm_server.sh`, `EVENTS_PORT`). The
router is the minimal one in `experiments/e_route/e_route.py`: it never reports which replica
served a request. Prefixwise (main at c2b8eee, unmodified) in front of it, in process, with
`--kv-events tcp://127.0.0.1:5557,tcp://127.0.0.1:5558`. Five sessions per mode, three turns
each, a ~1,600-token system prompt. Run by Muse from a fresh clone; no code changed.

**Reading it.**
- Every alternate T2 evidence names the right replicas both ways round (served by :5558 while
  :5557 held the prefix, and the reverse), with 101-102 of the previous turn's blocks still
  resident: the block the request needed was on the other replica.
- Alternate T3 returns to the first replica, which still holds T1: a hit (1,616 of ~1,685),
  correctly `none`.
- The labels are the KV-event endpoints (`:5557` is the replica on HTTP `:8001`).

**Not covered.** Data-parallel ranks inside one vLLM server (`--kv-events auto`; one L4 runs
one rank), real routers (llm-d, the SGLang router, production-stack, AIBrix: they must pass
the body's `session_id` and `vllm_xargs` through; Dynamo does not), eviction on a replica
(covered by E-evict on one engine), and real agent traffic.
