# Gateways round 1: Prefixwise behind four LLM gateways (2026-11-24)

Muse ran this in Colab on a fresh runtime, with no API keys and no spend. Code: `ac8c1a8f` (main). The checker
is `experiments/gateways/gateway_check.py`.

Each gateway's OpenAI and Anthropic upstream was `prefixwise serve` on port 4100. The cache mock sat behind it on
port 4101. Each check sends 5 five-turn conversations per format: one unchanged, and four with one change at turn
3. The checker reports three things:
1. whether every call was recorded;
2. which conversation id got through the gateway;
3. whether each conversation got `first_write, none, <change>, none, none`.

The result files are in [`2026-11-24-round1/`](2026-11-24-round1/). Muse sent them inside a PDF report, and they
were taken from that PDF's appendix. Every total below was recomputed here from the per-conversation results, not
read from the summary fields. The ledger (225 rows, which Muse says matches the sum of recorded calls) was not
sent.

## What it shows

- **Envoy AI Gateway works with Prefixwise as its upstream**, for OpenAI and Anthropic, streamed and not. It passed
  Prefixwise's own session header through. The cache reads (for example `4933/4959` on turn 2) are the same as in
  the self-check with no gateway.
- **Portkey's gateway works without streaming**, when `x-portkey-forward-headers` names the session header.
  - With streaming, Portkey answered every call with `{"status":"failure","message":"Something went wrong"}`.
  - Its log shows `TypeError: immutable` in its response-header code (`updateHeaders`). That function adds headers
    to the response Portkey received from upstream, and fails when that response's headers are read-only.
  - Prefixwise had already recorded each call and named each change.
  - Prefixwise streams in HTTP/1.0 with no `Content-Length`, ending the body by closing the connection. The cache
    mock answers with HTTP/1.1 and a length.
  - Whether Portkey streams correctly from other upstreams is untested. Round 2 has a control that streams straight
    to the mock.
- **Bifrost** never bound its port: `listen tcp 127.0.0.1:8080: bind: address already in use`. Port 8080 belongs to
  Colab's own server, so the 404s came from Colab, not Bifrost. Round 2 uses port 18080.
- **Plano** exited at start with `Missing API keys! sk-test not found`. It reads `access_key` as the name of an
  environment variable (its docs write `access_key: $OPENAI_API_KEY`). Round 2 sets the variables.

## Report quality

Muse's PDF flagged two places where the pasted cell output didn't match the result files: the Portkey streaming
tail and one summary line. A third went unflagged: the pasted Cell 3 (Envoy) lines show `ok` beside causes that are
all `none` for the injected kinds, which the checker can't print. The result files show the expected causes, and
the files are what is recorded here. The round 2 runbook asks for output to be pasted whole, never retyped.

## Not claimed

- Bifrost, Plano and Portkey streaming have not been shown to work.
- This round checked recording and session ids, not whether each gateway's translation keeps the prompt prefix
  identical across turns (LiteLLM's test B). Every request here went upstream in the same format it arrived in.
