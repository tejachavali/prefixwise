# Gateways round 1: Prefixwise behind four LLM gateways (2026-11-24)

Muse ran this in Colab on a fresh runtime, with no API keys and no spend. Code: `ac8c1a8f` (main). The checker
is `experiments/gateways/gateway_check.py`.

Each gateway's OpenAI and Anthropic upstream was `prefixwise serve` on port 4100. The cache mock, a fake provider
that caches by content, sat behind it on port 4101. Each check sends 5 five-turn conversations per format: one
unchanged, and four with one change at turn 3 (tools reordered, a timestamp in the system prompt, a system prompt
edit, an edit to the first user message). The checker reports three things:
1. whether every call was recorded;
2. which conversation id got through the gateway;
3. whether each conversation got the expected verdicts: `first_write` (the first turn writes the cache), `none`,
   the change (or `none`), `none`, `none`.

The result files are in [`2026-11-24-round1/`](2026-11-24-round1/). Muse sent them inside a PDF report, and they
were taken from that PDF's appendix. All 15 were compared with the appendix field by field. Every total below was
recomputed from the per-conversation results, not read from the summary fields. The ledger (225 rows, which Muse
says matches the sum of recorded calls) was not sent.

## What it shows

- **Envoy AI Gateway works with Prefixwise as its upstream**, for OpenAI and Anthropic, streamed and not. It passed
  Prefixwise's own session header through.
- **Portkey's gateway works without streaming**, with `x-portkey-forward-headers` naming the session header (not
  tried without it).
  - Streamed, Portkey answered all 25 calls with `{"status":"failure","message":"Something went wrong"}`. Its log
    shows `TypeError: immutable` in `updateHeaders`.
  - `immutable` is Node's error for changing the headers of a response that came straight from `fetch()`. The npm
    build that ran seems to have passed that response through on the streaming path. The Portkey source we read
    wraps it first (`new Response(readable, response)`), so it may differ from that build.
  - Why only streaming fails, and whether anything in Prefixwise's streamed response matters, is not shown. Round
    2 has a control that streams through Portkey straight to the cache mock.
- **Bifrost** never bound its port: `listen tcp 127.0.0.1:8080: bind: address already in use`. Port 8080 was held
  by a node process with pid 7, Colab's own server, so the 404s came from it, not Bifrost. Round 2 uses port 18080.
- **Plano** exited at start with `Missing API keys! sk-test not found`. It reads `access_key` as the name of an
  environment variable (Plano's quickstart writes `access_key: $OPENAI_API_KEY`). Round 2 sets the variables.

## Not claimed

- Bifrost, Plano and Portkey streaming have not been shown to work.
- This round checked recording and session ids. It did not check whether each gateway's translation keeps the
  prompt prefix identical across turns, as LiteLLM was tested in
  [test B](../../litellm/README.md). Every request here went upstream in the same format it arrived in.
