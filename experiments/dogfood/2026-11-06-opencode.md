## What broke or looked odd, and what was done

| Finding | Fix |
|---|---|
| opencode posts to `/messages` (base URL without `/v1`): 404 "unsupported path /messages" | `/messages`, `/chat/completions` and `/responses` are now accepted. Query strings such as Anthropic's `?beta=true` are forwarded. |
| `GET /v1/models` 404, `HEAD` 501 | Endpoints Prefixwise does not analyse now pass through to the upstream unchanged and are not recorded. HEAD is answered. |
| `claude-sonnet-4-6`, most of the traffic, unpriced | Added to the price table from Anthropic's official page (read 2026-11-07); the id is confirmed by this traffic. |
| "That failed request was still recorded in the ledger" | Not reproduced: an unsupported path and an upstream failure both record nothing, now pinned by tests. The ledger's 25 rows vs. opencode's 21 requests are likely its small-model side calls; unconfirmed. |
| Haiku side calls (titles, summaries) between Sonnet turns show as `model_switch`, and the switch back reuses Sonnet's prefix | `model_switch` is legitimate, so no false waste, but it hides causes on the main thread. Planned fix: track each model separately within a session. That changes how E1 scores model switches, so it gets its own PR with the E1 harnesses updated. |
| opencode ignored its project config and used its default model; its first full run bypassed the proxy | Not a Prefixwise bug. The planned `prefixwise run -- <cmd>` sets the environment so nothing can bypass it. |
