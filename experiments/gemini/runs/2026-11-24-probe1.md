# Gemini cache probe, first run (2026-11-24): mostly rate-limited, one pattern seen

Muse ran `gemini_cache_probe.py` (at `41e14c22`) in Colab, with a new free-tier key from Google AI Studio (issue
#170). Very little was measured, for three reasons:

- **The default model is gone for new keys.** `gemini-2.5-flash` returned 404 on every call ("no longer available to
  new users"), and the probe then crashed on the OpenAI-compatible endpoint's error, which is a JSON *list*, not an
  object. No file was written for that run.
- **The free tier rate-limited the Gemini 3 run.** On `gemini-3-flash-preview`, 15 of 50 calls succeeded; 21 got 429
  (quota) and 14 got 503 (overloaded). A recovery run straight after got 2 of 50 through, and the idle run 0 of 4.
- **So none of these were tested:** the prefix order, the explicit cache, repeats seconds apart, idle lifetime and
  the OpenAI-compatible endpoint's cached count. Every call of those parts failed.

The first attempt's file is [`2026-11-24-probe1/gem-probe-3-first-attempt.json`](2026-11-24-probe1/). It was taken
from the appendix of Muse's PDF report, and the error strings were rejoined where the PDF wrapped them. The table
below is read from it.

## What it suggests (to be confirmed: three reads)

- **Reads come in fixed chunks of about 4,096 tokens.**
  - Turn 3 repeated all 6,840 tokens of turn 2, but read 4,072. Two other reads were 4,075 and 4,080.
  - Three prompts of 962 to 2,839 tokens, sent again unchanged, never read anything.
  - If the chunk is 4,096 tokens, the minimum is one chunk, and a conversation reads only whole chunks of its
    prefix: up to about 4,095 tokens of a repeated prefix are paid in full on every turn. That is the same kind of
    rounding as DeepSeek's 128-token blocks, at 32 times the size.
  - The next run grows the conversation to ~13k tokens: reads should step to ~8,170 and ~12,260 if this holds.
- **`cachedContentTokenCount` is left out, not 0, when nothing is read.** `promptTokenCount` is always there. A
  reader that wants a number must treat the missing field as 0 when the usage is otherwise present.
- **The cached count is a subset of `promptTokenCount`**, which also matches Google's SDK documentation. A read of
  4,075 within a 6,840-token prompt leaves 2,765 uncached.
