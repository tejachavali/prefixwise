## Step 1: the template alone (CPU, `--cpu-template`)

**Qwen/Qwen3-4B.** The template drops the `<think>` block from every assistant message before
the last user query (`{%- if loop.last or (not loop.last and reasoning_content) %}` applies only
after `last_query_index`), so turn N's prompt plus output and turn N+1's prompt share exactly
turn N's prompt: `kept` shared 76 of 76+28 (reuse `prompt`), `stripped` shared 93 (reuse `full`,
because the client already removed what the template would). `enable_thinking: false` adds a
4-token tail stub (`<think>\n\n</think>\n\n`) and changes nothing before it (shared 76 of 76 and
80). No date clause (`renders_date: false`). A tool call with dict arguments rendered through
`tool_call.arguments | tojson`.

**unsloth/Llama-3.2-1B-Instruct** (no token needed). History is rendered as generated: `kept`
and `stripped` both reuse `full` (shared 125 of 97+28, 112 of 97+15). No thinking stub (tail
empty). **The template renders the date into the system header** (`Today Date: ` +
`strftime_now("%d %b %Y")` when the server defines `strftime_now`, which vLLM and transformers
do): `renders_date: true`, `where: "prefix"`, shared 19 of 97 tokens between two renderings with
different dates. On a Llama 3.x template every session's prefix is therefore recomputed once a
day, at the server's midnight, with no change in the request: a server-side `volatile_system`
that Prefixwise sees as `evicted` (inferred) or, with KV events, as `unknown` "not an eviction".

### What it shows

1. **Prompt-only reuse is the whole story on Qwen3.** Every turn read back the previous prompt,
   rounded down to a 16-token block (21 turns) or one block further short (4 turns: `nothink`,
   `toggle` and `tools` turns whose previous prompt ended in the generation prompt, the 4-token
   `<think>` stub included, which the rendered history never repeats), and recomputed the
   previous output: on `kept`, 2,258 tokens
   of "lost tail" across 5 turns against 2,864 read. This is the template's design (reasoning is
   dropped from history), not a client fault and not something an eviction verdict should name;
   `none` is right. `stripped` reads the same as `kept` on the engine, since vLLM's reasoning
   parser separates `reasoning_content` from `content` and the template re-renders the content
   without the `<think>` block it was generated after. `nothink` loses the output plus the 4-token
   stub (`<think>\n\n</think>\n\n` is in the generation prompt but not in the rendered history;
   the harness allows 4 tokens for it on top of a block).
2. **"Not an eviction" did not occur.** The prompt prefix is stable on Qwen3; the divergence is
   always at the boundary between the previous prompt and its output, which Prefixwise never
   expected to be reused. The Llama date clause (step 1) is the one known source of a true
   prefix divergence, and it fires once a day.
3. **A classifier bug.** The `toggle` turns were ordinary hits (400 of 407, 480 of 489: the prompt
   read to within one block, like every other turn) with a 4-token tail change, yet Prefixwise called them
   `param_rendered`, because the hit check demanded `cached >= previous prompt` exactly and
   the parameter change was judged before the block-rounded hit. The same numbers without the
   toggle were `none` through the "at least half" fallback. Fixed in the PR that adds this
   record: a read less than a reporting block short of the prefix (128 tokens at most, an eighth of
   the prefix at most, exact on Anthropic) is a hit, and the parameter change stays as secondary.
   The run instructions expected `toggle` to come out `cold` in the reuse column; it did not, for
   the same reason the hit is real: the stub is a tail, after everything the cache could serve.
